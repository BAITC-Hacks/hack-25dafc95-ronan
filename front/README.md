# ЭКТ Ассистент — frontend для Hackathon Trade

React + TypeScript + Vite. Витрина и помощник с двумя источниками данных: локальное демо frontend и API Node backend команды. Python вызывается только Node; frontend не выполняет операции корзины через Python.

## Запуск

Node.js 22.18+ и npm. В каталоге проекта:

```sh
npm ci
npm run dev
```

Откройте `http://127.0.0.1:5173`. Команды `dev` и `preview` обе закреплены на `127.0.0.1:5173` с `--strictPort`: при занятом порте запуск завершится ошибкой, а не перейдёт на другой origin. Запускайте только одну из них одновременно.

```sh
npm test
npm run build
npm run preview
```

Для браузерных проверок нужен Chromium Playwright (`npx playwright install chromium`):

```sh
npm run build
npm run test:e2e
```

Playwright запускает статическую production-сборку на 5173 и отдельный тестовый стенд на 5174. Стенд компилируется в `.test-build/`, не входит в `dist/` и не публикуется. В Windows sandbox этой сессии автоматическое завершение процессов webServer зависало: проверки повторно запущены с уже работающими preview-серверами и `E2E_EXTERNAL=1`; итоговый процесс завершился успешно. Обычный dev-сервер в sandbox ограничен доступом esbuild к родительским каталогам; production-сборка и `preview` работают.

`e2e/api-integration.spec.ts` включается через `E2E_API=1` при работающих Node API, Python ml_core и PostgreSQL. Он проверяет реальные запросы через proxy, пустую корзину до confirm, отсутствие удвоения при повторе, серверную отмену, две вкладки, `ml_status=ok`, Node `/cart` и frontend `/#/cart` после обновления. Для этой проверки корневой `.env` должен содержать локальный `ML_CORE_URL` и `ALLOWED_ORIGIN=http://127.0.0.1:5173`; ключи и сессионные токены в тест не записываются. `ml_status=ok` означает успешный вызов локального Python, а не работу LLM.

`build` включает строгую проверку TypeScript. `dist/` — готовый статический сайт. Не открывайте `index.html` через `file://`: нужен HTTP-хостинг. Корзина открывается по `/#/cart`; обновление этой страницы не требует серверного SPA-rewrite.

## Что действительно подключено

- Демокаталог из 10 синтетических товаров, подготовленные ответы и локальная демокорзина.
- Выбор склада и количества, отдельное предложение, явное согласие, изменение и удаление с подтверждением.
- Цена в тенге, параметры, остатки, тестовый HTML-паспорт, объяснение аналога.
- Прикрепление Excel, Word, PDF и JPEG с именем, размером, удалением и проверкой расширения/размера.
- Статическая страница локальной корзины и сохранение корзины после обновления страницы.

Данные не получены от ekt.kz. Локальная демокорзина не связана с реальным магазином. Оформление заказа отсутствует. Frontend не читает содержимое документов и не запускает ML. Демо не загружает файл; показанный пример подбора явно обозначен как подготовленный и не зависит от файла.

## Режимы и настройки

В верхней полосе явно выбирается `Демо` или `API`. Начальное значение задаётся через `.env` по образцу `.env.example`:

| Переменная               | Значение                                                |
| ------------------------ | ------------------------------------------------------- |
| `VITE_DATA_MODE`         | `demo` (по умолчанию) или `api`                         |
| `VITE_MAX_ATTACHMENT_MB` | Максимальный размер одного вложения, по умолчанию 10 МБ |

Все `VITE_*` публичны: **никогда не помещайте туда секреты**. API-адаптер вызывает маршруты Node через `/api` proxy; перед запуском нужен backend на `127.0.0.1:8000` и `ALLOWED_ORIGIN=http://127.0.0.1:5173` в локальном корневом `.env`. Выбранный режим сохраняется только в `sessionStorage` вкладки; cookie `HttpOnly`, CSRF-токен остаётся в памяти. Демоответы не подменяют ошибки API. Переключение очищает переписку и активное предложение; режим нельзя переключить во время выполняемой или невыясненной операции.

## Архитектура и встраивание

- `src/Assistant.tsx` — представление помощника, получает типизированный controller.
- `src/useAssistant.tsx` — состояние сессии и orchestration: сообщения, подтверждения, сверка после сбоя, общая корзина.
- `src/components.tsx` — карточки товаров и строк корзины.
- `src/assistant.css` — стили внутри `.ekt-assistant`; `src/products.css` — иллюстрации, ограниченные помощником и витриной; `src/site.css` — демонстрационная витрина.
- `src/types.ts` — ожидаемый интерфейс источника данных.
- `src/data.ts` — локальный демоисточник и экспорт `createApiSource` из подключённого `src/apiSource.ts`.
- `src/cartEngine.ts` — чистая критичная логика расчёта и проверки согласия.

Для переноса используйте `Assistant`, его controller и общие визуальные примитивы. Проверка встраивания в ekt.kz не проводилась: нужно согласовать React-монтирование или iframe, стили хоста, CSP, маршрутизацию, авторизацию и доступность. Имена CSS ограничивают влияние помощника, но это не Shadow DOM и не доказанная изоляция от произвольных стилей хоста.

## Интеграция с Node API

`src/apiSource.ts` реализует `DataSource` по `../docs/API_CONTRACT.md`: список/карточка, чат, сессия, demo proposal, confirm, cancel, чтение корзины и сверка статуса. Только synthetic-товар допускает добавление через API; изменение и удаление строк пока отключены. Оригинальный локальный демо-режим продолжает работать отдельно. Для API-корзины `cartUrl` указывает на frontend `/#/cart`; Node также отдаёт проверочную страницу `/cart` для той же cookie.

Node сохраняет тип товара и заданный ток из исходного поискового запроса; Python помогает только с порядком уже допустимых кандидатов. При неподтверждённом токе или конфликте характеристик товар не выдаётся как подтверждённое техническое совпадение. Точный поиск `027228` и `200300285_` сохраняет карточку 515291 с `SPEC_CONFLICT`. Опубликованная цена снимка отображается отдельно с пометкой об неизвестной валюте, не разрешая покупку. Опциональный `AI_MODE=openai` меняет только формулировку ответа; ключ остаётся на Node, а товарные факты и корзина не передаются под управление модели. NVIDIA не подключена.

| Операция                     | Ожидаемое поведение                                                                                                                                                            |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `getCatalog()`               | Товары: стабильный id, артикул, название, nullable цена, единица, минимум, шаг, остатки отдельно по складам, параметры, nullable документ                                      |
| `getCart()`                  | Авторитетная корзина `{revision, lines}`; линия идентифицируется товаром и складом                                                                                             |
| `chat(text)`                 | Текст и необязательные карточки; аналог с причиной, совпадающими параметрами и отличиями                                                                                       |
| `upload(file)` (опционально) | Предоставленный командой механизм загрузки и ожидания результата обработки. Promise завершается только после обработки; без механизма показывается отсутствие обработки        |
| `propose(intent)`            | Серверная котировка конкретного изменения: уникальный id операции, revision корзины, товар, склад, было/станет, цена, остаток                                                  |
| `commit(proposal)`           | Атомарная проверка актуальности условий и применение один раз по id. Возвращает `applied` и актуальную корзину либо `changed` с новой котировкой **и новым id** без применения |
| `cancel(proposalId)`         | Отменить серверное предложение; UI показывает отмену только после успешного ответа. При ошибке успех не объявляется |
| `reconcile(operationId)`     | Актуальная корзина и статус именно этой операции: `applied`, `not-applied`, `unknown`                                                                                          |
| `cartUrl`                    | Адрес корзины текущего режима; для API demo это `/#/cart`, не корзина EKT                                                                                                       |

Сервис обязан атомарно проверять цену, доступность выбранного склада, минимальную партию, шаг, revision, права пользователя и идемпотентность. Сервер не должен доверять клиентской цене. При изменении условий нужен новый id и новое согласие; нехватка остатка не означает разрешение уменьшить количество. Цены в демо целые; для реальных цен согласуйте minor units/правила округления и НДС.

`commit` запускается только по кнопке согласия либо точной фразе `да, добавь`, `да, добавить`, `да, подтверждаю` (без учёта регистра, допускается конечный `.` или `!`). Одно `да` и любой иной текст не являются согласием. Разрешено только одно активное предложение; новое заменяет предыдущее. Черновик количества и рекомендации корзину не меняют. Закрытие панели не подтверждает операцию.

При неоднозначной ошибке изменения frontend сначала вызывает `reconcile`; пока статус неизвестен, новые изменения заблокированы. Результат `not-applied` прекращает предложение: нужно создать новое и согласиться снова. Возврат реальной корзины обязателен при успешном изменении. Повторная слепая отправка не выполняется. Для загрузки файлов команда должна определить ограничения, серверную проверку формата, сроки хранения, авторизацию, прогресс/опрос и безопасный повтор; текущий интерфейс показывает только фактически известные стадии, не выдуманный процент.

Если другая вкладка обновила CSRF-токен общей сессии, только ответ `CSRF_INVALID` разрешает один повтор: frontend заново вызывает `/api/session` и отправляет то же действие с тем же телом и `Idempotency-Key` confirm. Второй отказ, сетевая ошибка или другая API-ошибка не запускают автоматический повтор. Проверки CSRF и Origin остаются включены.

Нужны также CORS/CSRF-политика, безопасные URL документов и корзины, формат ошибок, обработка истечения сессии, таймауты и серверная защита реальной корзины. LLM не вызывается из браузера.

## Демо для показа

1. «Кабель ВВГнг-LS 3×2,5» / `DEMO-1001`: параметры, 120 м в Алматы и 45 м в Астане, 485 ₸/м, минимум/шаг 5 м. Тестовый документ открывается отдельно.
2. «Аналог ВВГ 3×2,5»: исходная позиция отсутствует; альтернатива с совпадениями и отличиями. Совместимость не гарантируется.
3. «Условия доставки»: подготовленные условия оплаты, доставки и партии, явно не условия магазина.
4. «УЗО» / `DEMO-2002`: остаток 3 шт. Добавьте 2, затем запросите ещё 2 — превышение с учётом корзины блокируется.
5. «Все товары»: 10 позиций, единицы м/шт/упак/кг. `DEMO-4003` — дробный шаг 0,5 кг. `DEMO-3002` — неизвестные цена и остаток.
6. «Ошибка»: предсказуемый искусственный сбой запроса для проверки ошибки и повтора без дублирования сообщения. Повтор тоже завершится ошибкой; это не реальная сеть.
7. Неизвестный запрос: сообщение об отсутствии подготовленного сценария.

## Хранение и ограничения

Только демокорзина сохраняется в `localStorage` (`ekt-demo-cart-v1`). Переписка и содержимое файлов в постоянное хранилище не записываются. Сброс демо удаляет сохранённые позиции и очищает текущую сессию. Если запись в storage недоступна, корзина работает только до обновления страницы. Другой браузер/устройство/вкладка не синхронизируются; открывайте демо в одной вкладке. Локальное хранилище изменяемо пользователем и не служит защитой реальной корзины. Список выполненных id существует только в памяти демосессии; долговременная идемпотентность — обязанность сервиса команды.

Проверка расширения на клиенте не является проверкой содержимого файла. Тексты React экранирует; `dangerouslySetInnerHTML` не используется. Товарные факты и правила покупки остаются на Node; браузер не получает прямой адрес EKT API. Внешний шрифт Manrope имеет системный fallback.

## Публикация на Netlify

Доступ к хостингу не предоставлен; публичный адрес не создан.

1. Выполнить `npm ci`, `npm test`, `npm run build`.
2. В Netlify выбрать ручную загрузку и загрузить **каталог `dist`**, содержащий `index.html`, `assets` и тестовый документ. При ручной загрузке Netlify сам сборку не запускает.
3. Открыть выданный HTTPS-адрес; пройти добавление с согласием.
4. Перейти на `/#/cart`, обновить страницу и убедиться, что локальная корзина сохранилась.
5. Проверить мобильный экран, документ и сброс демо на публичном адресе.

Hash-маршрут отправляет серверу только `/`, поэтому обновление корзины работает без функций или серверных маршрутов. При подключении Git: build command `npm run build`, publish directory `dist`, base directory — каталог этого проекта. Настройки также приведены в `netlify.toml`.

Официальная инструкция: https://docs.netlify.com/deploy/create-deploys/

## Проверки

`npm test` проверяет отсутствие согласия, отмену/устаревание, остаток с учётом корзины и отдельного склада, шаг, неизвестные данные, изменение условий, идемпотентность id и согласие на изменение/удаление. Браузерные сценарии и фактически запущенные результаты описаны в `QA.md`.

Финальный проход 23 сентября 2026: 17 frontend unit-тестов и `npm run build` прошли. Регрессии API-адаптера проверяют ожидание ответа cancel, ошибку отмены, сохранение кода ошибки, один CSRF retry с неизменным confirm key/body и отсутствие повтора при сетевой ошибке. Шесть браузерных сценариев `editing.spec.ts`/`flow.spec.ts` также прошли; результаты реального четырёхкомпонентного API-прогона приведены в корневом README.
