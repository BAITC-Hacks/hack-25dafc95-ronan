# Node ↔ Python ml_core, реализованный локальный контракт

Python HTTP-адаптер запускается `python -m ml_core.service` на `127.0.0.1:8100` (`ML_CORE_PORT` меняет порт). Node использует `ML_CORE_URL=http://127.0.0.1:8100`. Отдельная инициализация Python-каталога для этого пути не нужна: Node передаёт до 50 кандидатов из своего каталога, Python возвращает не более 20 ID. Адаптер использует ранжирование `ml_core.catalog`, но не скачивает товары EKT и не считает Python-данные товарными фактами.

Node вызывает `POST {ML_CORE_URL}/v1/parse-rank` с JSON:

```json
{
  "message": "Есть 027228 в Астане?",
  "candidates": [
    { "id": 515291, "name": "027228 АВ DRX250 MT 3ф 160А 18ka Legrand (1)", "article": "200300285_" }
  ]
}
```

Ответ Python:

```json
{ "query": "027228", "ranked_ids": [515291] }
```

`query` — подсказка длиной до 100 символов; `ranked_ids` — упорядоченное подмножество переданных candidate ID. Node проверяет форму, уникальность и принадлежность каждого ID, берёт карточки, цены и остатки только из своего каталога. Python не получает session cookie, CSRF token, cart proposal и инструмент записи; ответ Python никогда не подтверждает корзину. При таймауте 800 мс, ошибке HTTP или неверном JSON Node возвращает контролируемый fallback. Контракт проверен локальным HTTP-вызовом; участнику ML нужно подтвердить его как публичную границу команды.

Python сохраняет ограничения типа и заданного тока в естественном запросе; латинское название бренда вроде `Legrand` не заменяет весь запрос как артикул. Для точного идентификатора сохраняются ведущие нули и подчёркивания (`027228`, `200300285_`, `DEMO_001`). Проверка Python по названиям служит предварительным отбором, а не доказательством характеристик.

Node независимо фильтрует результаты по **исходному сообщению**, проверяя тип и ток по каталогу; `query` и `ranked_ids` не могут отменить ограничения запроса. При недоступности Python применяются те же ограничения. В данных снимка название само по себе не подтверждает ток; если данных недостаточно или они противоречат друг другу, Node сообщает об отсутствии подтверждённых совпадений в просмотренной части каталога. Товар 515291 с конфликтом 160 А / 250 А исключается из уверенного подбора по току, но остаётся доступен по точному идентификатору с предупреждением `SPEC_CONFLICT`.

`ml_status=ok` в Node `/api/chat` означает только успешный валидный ответ локального HTTP-сервиса. Реализация использует регулярные выражения и строковое ранжирование; OpenAI/NVIDIA и обученная модель в этом пути отсутствуют. Рабочий режим Node — `AI_MODE=stub`; `AI_MODE=openai` явно отклоняется при запуске, а добавление внешнего ключа не включает LLM.
