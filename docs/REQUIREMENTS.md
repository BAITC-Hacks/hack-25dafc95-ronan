# Требования из материалов пользователя

Источник: приложенные пользователем скриншоты HackAlem AI, описание доступа к API и JSON-ответы. Ниже — пересказ требований, а не новая спецификация партнёра. Архитектурные решения команды отделены в PLAN.md и CODEX_PROMPT.md.

## Кейс и пользователь

ИИ-ассистент-консультант и помощник сайта ekt.kz, партнёр — ТОО «Электрокомплект». Основной пользователь — частный покупатель или закупщик компании, выбирающий электротехническую продукцию.

Проблема: для характеристик, сертификатов, проверки наличия, поиска аналогов и условий покупки клиенты обращаются к менеджерам. Ценность решения: быстрее принять решение о покупке, сократить отток на консультации и освободить время менеджеров для сложных сделок.

Сценарий: клиент открывает чат, спрашивает о товаре, наличии, аналогах или условиях; получает ответ; после явного подтверждения позиции добавляются в корзину; клиент переходит по ссылке для оформления.

## Вход и выход

Вход: свободный текст, изображения и вложения Excel, Word, PDF, JPEG; контекст диалога в рамках сессии; каталог и остатки. Примеры вложений: фото товара, спецификация, накладная.

Выход: текстовый ответ о товаре, аналогах и условиях; при подтверждении — обновлённая корзина и прямая ссылка на её страницу/оформление. Допустимая задержка в ТЗ описана как «единицы секунд»; численный SLA не задан.

## Данные

Каталог и остатки доступны через выгрузку или тестовый API. В перечне ожидаемых полей: артикул, название, категория, основные характеристики, сертификаты при наличии, цена, остаток по складам и статус наличия. Для прототипа достаточно репрезентативной выборки.

Для разработки и демонстрации разрешены анонимизированные или синтетические данные с сохранением структуры полей. Это не подтверждение, что организаторы автоматически примут любую имитацию интеграции корзины; способ демонстрации стоит согласовать.

## Пять обязательных сценариев

1. Ответ о наличии, технических характеристиках и сертификатах по каталогу. Проверка: запрос существующего артикула возвращает корректные данные и ссылку/файл сертификата, если он присутствует в базе.
2. При отсутствии товара — релевантный аналог с кратким объяснением. Проверка: позиция с нулевым остатком возвращает минимум один аналог.
3. Содержательный ответ об оплате, доставке и минимальной партии на основании условий магазина.
4. Добавление только после явного подтверждения клиента, с учётом количества и наличия. Без явного «да, добавь» корзина не меняется; после подтверждения количество не превышает остаток.
5. После добавления — прямая ссылка, ведущая к актуальному состоянию корзины/оформлению.

## Опционально в ТЗ

Казахский язык; сопутствующие товары; история для авторизованных пользователей; эскалация сложных вопросов менеджеру.

Вложения перечислены во входных данных, а не в разделе «Опционально». Поэтому их сокращённая поддержка в раннем прототипе — временное ограничение реализации, которое нужно открыто указать, а не переобозначать как необязательное требование.

## Ограничения и артефакты

Нельзя менять корзину или оформлять заказ без явного подтверждения; сообщать недостоверную цену или наличие; запрашивать или хранить платёжные данные клиента.

Нужны приватность, защита корзины/заказа от несанкционированных действий, объяснимость аналогов, совместимость с текущей платформой, desktop и mobile.

Артефакты: репозиторий и README с архитектурой, запуском прототипа и описанием использованных данных.

## Предоставленный API

Только подтверждённые материалами маршруты:

```text
GET https://ekt.kz/api/products
GET https://ekt.kz/api/products?page=2
GET https://ekt.kz/api/products/detail?id=515291
```

Авторизация: HTTP Basic Auth. Значения credentials намеренно не включены в пакет. Вносить их вручную в локальное окружение.

Документация поиска, корзины, заказа, сертификатов, условий покупки, лимитов API, единиц количества и семантики отдельных свойств не предоставлена. Наличие других маршрутов не проверялось.
